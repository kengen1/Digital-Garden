## 📝 Problem Details

- **Title:** `1526. Minimum Number of Increments on Subarrays to Form a Target Array`
- **Link:** https://leetcode.com/problems/minimum-number-of-increments-on-subarrays-to-form-a-target-array/
- **Difficulty:** #Hard 
- **Tags/Categories:** `{{tags/categories}}`

> input array `target`
> input array `initial` --> all elements initialize to `0`
> both `target` and `initial` have the same size 
> in one operation you can choose any subarray from `initial` and increment each value by one
> return the minimum number of operations to form a `target` array from`initial`
## 💭What Were My Initial Thoughts?

```
Brute force:
- start from the first element and keep incrementing subarrays greedily
- at every step, find the leftmost value that needs incrementing and apply an increment to the **largest possible subarray** that matches `target`.
- this would involve **many unnecessary operations** since overlapping subarrays can be merged.

Optimal approach:
- Instead of simulating **explicit subarray increments**, we should analyze **how much each element increases compared to the previous one**.
- Each increase at position `i` is **independent** of previous increases at earlier indices.
- **Key Idea:** Instead of tracking every subarray operation, we can compute the total number of necessary increments **just by looking at the height differences** between adjacent elements.```
